## MODIFIED Requirements

### Requirement: Local sync script

The template repo SHALL provide a script, runnable from an already-bootstrapped
child repo with no instance repo clone (`python3 -m panopticon.sync` or
equivalent), that fetches the instance repo's current default-branch copies of
the child's downloaded skills and vendored local-tooling modules and reconciles
the complete fixed set of managed child caller workflows. The script SHALL
generate each caller from the child configuration and the instance's current
provider configuration, and SHALL create missing callers or overwrite
content-different callers unconditionally. The script SHALL NOT protect any
managed file at the child-repo layer — the user's own review of the resulting
`git diff`/`git status` before committing is the only safety mechanism,
matching the bootstrap installer's existing idempotent overwrite model.

Given a `--check-updates` flag, the script SHALL run as a pure dry run: it SHALL
report every skill, tooling module, and managed caller workflow that would
change, using content-based comparison, and SHALL NOT write any file.

#### Scenario: Default run refreshes a missing resource-sync caller

- **GIVEN** an initialized child lacks
  `.github/workflows/panopticon-resource-sync.yml`
- **WHEN** local sync runs without flags against an instance with a valid
  provider configuration
- **THEN** it creates the generated resource-sync caller together with any
  other drifted managed resources

#### Scenario: Default run refreshes a stale provider caller

- **GIVEN** a child caller workflow differs from the text generated by the
  instance's current provider contract
- **WHEN** local sync runs without flags
- **THEN** it overwrites that caller with the generated current text

#### Scenario: --check-updates reports caller drift without writing

- **GIVEN** a managed caller workflow is missing or differs from generated text
- **WHEN** local sync runs with `--check-updates`
- **THEN** it reports the workflow path and does not create or modify it

#### Scenario: Invalid instance provider configuration fails before caller writes

- **GIVEN** the child can read its local configuration but the instance provider
  configuration is absent or invalid
- **WHEN** local sync runs
- **THEN** it exits with a configuration error and does not write managed caller
  workflows
